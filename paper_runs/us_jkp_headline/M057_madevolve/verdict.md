# M057: MadEvolve evolutionary trading-system optimization

Status: **closed not evaluable on monthly U.S./JKP data**.

MadEvolve's headline strategy is not a fixed published factor. Five evolutionary islands use multiple LLMs to mutate an alpha forecaster and BTCUSD trading-system code, preserve diverse MAP-Elites, migrate candidates, and select the best program under a limit-order simulator with explicit fills, fees, and market impact. A direct first-party chain links the paper to `madevolve.org` and then to coauthor Tianyi Li's public framework repository.

That repository is substantive general-purpose evolutionary infrastructure. Controlled fixtures execute its patcher, grid, islands, elite vault, and artifact store. But the current repository remains at the audited head and still contains no BTCUSD adapter, market snapshot, trading code, paper configuration, seed, model-call trace, candidate program, best evolved system, Optuna study, Claude Code ideas tree, orders, holdings, or return arrays. The package also has a missing declared dependency and a syntax error in two template modules, although those software defects are secondary to the absent trading payload.

The appendix baseline is incomplete pseudocode with unreleased project dependencies; it is not the headline evolved system and cannot provide a defensible score partial. JKP cannot repair that boundary because there is no MadEvolve candidate program to transfer. Inventing a new factor, objective, execution model, and search would create a different system, while replacing the paper's limit-order object with a generic monthly decile score would discard what MadEvolve evolves.

No return path is fabricated. None of 214 numeric result units or 21 empirical panels was regenerated. This closure does not establish that the reported BTCUSD results are false; it records that the public release supplies framework mechanics but no causal trading strategy or experiment lineage.
